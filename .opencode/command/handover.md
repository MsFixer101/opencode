Write a handover for the current work so the next instance can pick it up cleanly.

Carry context, not impressions — about the work, never the principal. Cut anything that isn't load-bearing.

**Why** — the reason the work exists, in the principal's own words. Quote it; don't paraphrase — the paraphrase is what dies across hands. The gate: if the handover loses the intent, it has failed, however complete the rest looks.

**What** — the deliverable, and where it stands now. The concrete output, not the topic.

**How** — the build: the code, the connections, the decisions made. Tied to What.

**When** — what's next. The literal next move and where it's heading. The successor reads this first.

**Context / background** *(optional, last)* — anything else load-bearing that doesn't fit above: orienting background, key links and materials, dependencies. Same rule as the rest — context, not impressions.
